# i18n: gettext, dominios y cambio en runtime

Diseño del servicio de internacionalización de la consola y los juegos. La
decisión está en el [ADR 0005](../adr/0005-i18n-gettext-babel.md); el ticket es
[#12](https://github.com/skalanux/toxinator/issues/12).

> **Estado**: decidido; implementación pendiente. El repo todavía no tiene
> código del runtime.

## Objetivos

- Español por defecto e inglés como segundo idioma, con cambio en runtime.
- Textos fuera del código, con claves estables y traducibles.
- Un catálogo por paquete (consola o juego), sin que un juego pise textos de la
  consola.
- Fallback explícito y probado, sin pantallas rotas por una traducción faltante.
- Números, fechas y porcentajes con formato del locale.
- Pipeline simple para desarrollar, traducir y validar en CI.

**No objetivos**

- Más idiomas que `es`/`en` en este esfuerzo (el diseño no los impide).
- RTL, fuentes por locale o traducción de contenido generado por IA.
- Idioma por perfil: el idioma es global de la consola.
- Traducir logs de desarrollo; los logs van en inglés.
- Weblate/Pontoon en el primer corte; los `.po` se editan por PR.

## Locales y negociación

Locales soportados: `es` (default) y `en`. Las variantes regionales (`es-AR`,
`es_419`, `en-US`, `en_GB`) se normalizan a su idioma base; no hay traducciones
regionales por ahora.

Orden de resolución:

1. Ajuste guardado en `settings.toml` (`language = "es" | "en"`).
2. `TOXINATOR_LANG` (dev/tests, o primer arranque sin ajuste).
3. Locale del sistema: `LANGUAGE` (lista separada por `:`), después `LC_ALL`,
   `LC_MESSAGES` y `LANG`.
4. `es`.

`C`, `POSIX`, vacío o un idioma no soportado caen a `es`. El ajuste guardado
manda; `TOXINATOR_LANG` no lo pisa. Los tests usan un `XDG_CONFIG_HOME` temporal
para arrancar sin ajuste.

La UI de ajustes muestra los nombres en su propio idioma: **Español**,
**English**. No se traducen.

## Servicio y API

`I18nService` vive en `toxinator.core` y se expone a los juegos a través de
`toxinator.api` como `ctx.i18n`. Es main-thread only: los cambios de idioma se
aplican en el game loop, no desde el thread del WebSocket.

```python
class I18nService:
    locale: str
    available_locales: tuple[str, ...]

    def set_language(self, locale: str) -> None: ...
    def effective_locale(self, domain: str | None = None) -> str: ...

    def tr(self, key: str, *, domain: str | None = None, **params: object) -> str: ...
    def trn(
        self,
        key_one: str,
        key_other: str,
        count: int,
        *,
        domain: str | None = None,
        **params: object,
    ) -> str: ...

    def format_number(self, value: float, *, domain: str | None = None) -> str: ...
    def format_percent(self, value: float, *, domain: str | None = None) -> str: ...
    def format_date(self, value: date, *, domain: str | None = None) -> str: ...
    def format_datetime(self, value: datetime, *, domain: str | None = None) -> str: ...
    def format_time(self, value: time, *, domain: str | None = None) -> str: ...
```

El `GameContext` entrega un proxy con `domain` fijado al id del juego; el
launcher usa el proxy de `toxinator`. Así el código de un juego llama
`ctx.i18n.tr("menu.play")` sin repetir el dominio, y no puede escribir en el
dominio de la consola.

`set_language` valida el locale, cambia el catálogo activo, persiste el ajuste y
emite `LanguageChanged(old, new)`. Si el locale es el mismo, es no-op. Si falla
la persistencia, loguea y sigue: el cambio aplica a la sesión.

## Dominios y catálogos

- Dominio de la consola: `toxinator`.
- Dominio de un juego: el `id` del manifest (`maldito-pino`).
- Cada dominio tiene su `.pot` y sus `.po`/`.mo` dentro de su paquete.
- `toxinator.*` está reservado; un juego no puede registrar ni sobrescribir ese
  dominio.
- El `GameHost` carga los catálogos de un juego desde su paquete sin importar el
  código del juego.

Layout estándar de gettext:

```text
src/toxinator/locales/
  toxinator.pot
  es/LC_MESSAGES/toxinator.po
  en/LC_MESSAGES/toxinator.po
  es/LC_MESSAGES/toxinator.mo   # generado, gitignored
  en/LC_MESSAGES/toxinator.mo   # generado, gitignored

games/maldito-pino/src/maldito_pino/locales/
  maldito-pino.pot
  es/LC_MESSAGES/maldito-pino.po
  en/LC_MESSAGES/maldito-pino.po
```

El manifest declara:

```toml
[game]
id = "maldito-pino"
name_key = "game.name"
description_key = "game.description"
locales = ["es", "en"]
default_locale = "es"
```

`name_key` y `description_key` se resuelven en el dominio del juego. Si el
manifiesto omite `locales`, se asume `["es"]` y `default_locale = "es"` con un
warning; `default_locale` debe estar en `locales`.

## Claves, placeholders y plurales

Formato de clave: `area.component.element`, minúsculas, ASCII, separadas por
puntos. Ejemplos: `launcher.featured.play`, `settings.language.title`,
`common.back`, `error.controller.missing_motion`.

- No se construyen claves en runtime con f-strings ni concatenación.
- No se usa `msgctxt`: si una palabra cambia según contexto, se usan claves
  distintas (`common.open_action`, `common.open_status`).
- Las claves de plural terminan en `.one` y `.other`.
- Los comentarios `# Translators:` se extraen con Babel y explican dónde/cuándo
  aparece el texto cuando la clave no alcanza.

Placeholders con nombre, entre llaves: `{name}`, `{count}`, `{language}`. Nunca
posicionales (`{0}`), `%s` ni f-strings en copy. Las llaves literales se escriben
`{{`/`}}`. El servicio formatea con `str.format_map` y los tests/CI comparan el
conjunto de placeholders entre la clave y cada traducción.

Plurales con dos claves estables:

```python
ctx.i18n.trn(
    "launcher.players.one",
    "launcher.players.other",
    count,
    count=count,
)
```

```po
msgid "launcher.players.one"
msgid_plural "launcher.players.other"
msgstr[0] "{count} jugador"
msgstr[1] "{count} jugadores"
```

`trn` inyecta `count` en los parámetros si no se pasó. La traducción puede no
usar `{count}` (por ejemplo, “Jugadores: {count}” sí, “Plantel completo” no).
Gettext elige la forma según el `Plural-Forms` del catálogo; `es` y `en` usan
`nplurals=2; plural=(n != 1);`.

## Errores y fallback

Orden para `tr`/`trn`:

1. Catálogo del locale activo (o el efectivo del dominio).
2. Catálogo del locale default del dominio (`es` para la consola).
3. En dev: `⟦key⟧`; en release: la clave. En ambos casos se loguea una vez.

Un parámetro faltante (`KeyError` de `format_map`) se loguea y devuelve la
plantilla sin formatear; los tests lo tratan como error. Un dominio desconocido
devuelve la clave y loguea. La UI nunca se cae por i18n.

El modo dev se activa con `toxinator dev` o `TOXINATOR_DEV=1`; el release usa el
default. El fallback por clave es una red de seguridad: CI exige paridad, así que
en `main` no debería activarse.

## Cambio de idioma en runtime

`set_language("en")`:

1. Valida que `en` esté soportado.
2. Descarta los catálogos cacheados y carga los del nuevo locale (lazy por
   dominio).
3. Persiste `language = "en"` en `settings.toml`.
4. Emite `LanguageChanged(old="es", new="en")` en el bus de eventos.

El launcher se re-renderiza al recibir el evento. Cada juego decide si escucha y
vuelve a pedir sus textos; si no lo hace, sus nodos de texto mantienen lo que ya
mostraban hasta el próximo render. No se reinicia el proceso ni se recarga el
juego. El controlador web recibe el cambio por WebSocket y vuelve a pedir su JSON.

## Assets localizados

Convención por paquete:

```text
assets/
  common/    # arte sin texto, fuentes, sonidos neutros
  es/        # overrides con texto o VO en español
  en/        # overrides con texto o VO en inglés
```

`AssetService.locate(relative_path, domain=None)` busca, en orden:

1. `assets/<locale efectivo>/<path>`
2. `assets/common/<path>`
3. `assets/<default_locale>/<path>`
4. Error `AssetNotFound`.

Los assets con texto (título, tutoriales, VO) se localizan; las fuentes y el
arte sin texto van en `common/`. No se usan sufijos por idioma
(`title_es.png`) dentro de `common/`.

## Juegos sin el idioma activo

Si el locale activo no está en `manifest.locales`, el dominio del juego usa su
`default_locale` para textos y assets; la consola sigue en el locale activo. El
launcher muestra un aviso no bloqueante en la ficha del juego:

> Este juego no está disponible en inglés; se muestra en español.

El aviso se traduce con el catálogo de la consola y usa `{language}` y
`{default_language}`. El juego se puede lanzar igual. No se mezclan textos de la
consola con los del juego.

## Formato de números, fechas y porcentajes

El servicio envuelve Babel; los juegos no importan `babel` (frontera
`toxinator.api`). Todos los métodos usan el locale efectivo del dominio y la
timezone local del sistema.

- `format_number(1234.5)` → `1.234,5` en `es`, `1,234.5` en `en`.
- `format_percent(0.42)` → `42 %` en `es`, `42%` en `en` (Babel decide el
  espaciado).
- `format_date(date(2026, 11, 17))` → `17 nov 2026` / `Nov 17, 2026`.
- `format_datetime`, `format_time` con los formatos `short`/`medium` de Babel.

No hay formato relativo (“hace 2 días”) en el primer corte; se agrega si un
juego lo pide. Los formatos personalizados se pasan como `format=` cuando haga
falta, pero el default alcanza para el launcher y Maldito Pino.

## Controlador Android (`controller-web`)

Las strings del PWA viven en el dominio `toxinator`, bajo `controller.*`. La
consola sirve un JSON generado desde el mismo catálogo:

```http
GET /api/i18n/controller?lang=es
```

```json
{
  "lang": "es",
  "strings": {
    "controller.connected": "Conectado",
    "controller.move": "Mover",
    "controller.calibrate": "Calibrar"
  }
}
```

- Solo se exportan las claves con prefijo `controller.`; no se filtran textos
  internos de la consola.
- El QR incluye `lang=es`; el PWA arranca en el idioma de la consola, no en el
  del teléfono.
- Si el idioma cambia mientras el celular está conectado, la consola manda
  `{"type": "language", "lang": "en"}` por el WebSocket de control y el PWA
  vuelve a pedir el JSON.
- El PWA aplica las strings con atributos `data-i18n` y una función `t()`; no
  tiene build step ni catálogo propio.
- Si el fetch falla, muestra un estado de error/offline; no hay textos
  hardcodeados de respaldo. El controlador necesita la consola de todos modos.

## Pipeline

Un solo script, `scripts/i18n.py`, con una tabla explícita de dominios:

```python
DOMAINS = {
    "toxinator": "src/toxinator",
    "maldito-pino": "games/maldito-pino/src/maldito_pino",
}
```

Comandos:

```bash
uv run python scripts/i18n.py extract
uv run python scripts/i18n.py update --locale es --locale en
uv run python scripts/i18n.py compile
uv run python scripts/i18n.py check
uv run python scripts/i18n.py pseudo   # genera qps para dev
```

- `extract` corre `pybabel extract -F babel.cfg -c "Translators:" -k tr -k trn:1,2`
  por dominio y escribe `<pkg>/locales/<domain>.pot`.
- `update` corre `pybabel update` por locale; marca nuevas, obsoletas y fuzzy.
- `compile` corre `pybabel compile` y escribe los `.mo` (gitignored).
- `check` valida paridad, placeholders, fuzzy/vacíos/obsoletos, plurales y que
  el `.pot` commiteado coincida con el extraído del código.
- `pseudo` genera `qps` desde `en` en `build/i18n/`, sin tocar los catálogos
  reales.

`.pot` y `.po` se commitean; `.mo` no. El build de la consola compila antes de
empaquetar; `toxinator dev` compila al arrancar y en cada cambio.

## CI y workflow

Toda clave nueva entra en el mismo PR con `es` y `en`, placeholders idénticos y,
si hace falta contexto, un comentario `# Translators:`. CI bloquea:

- claves faltantes en `es` o `en`;
- `fuzzy`, `msgstr` vacío o igual a la clave;
- claves huérfanas u obsoletas;
- placeholders distintos entre idioma y traducción;
- plurales incompletos o con `nplurals` inconsistente;
- `.pot` desactualizado respecto del código.

`main` siempre compila y se puede shipear. No se mergean traducciones a medias.
Weblate/Pontoon queda para cuando haya más traductores; por ahora se editan los
`.po` por PR y se revisan como código. No se commitea traducción automática sin
revisión.

## Hot reload

En `toxinator dev`, un task de Panda3D revisa cada segundo los mtimes de los
`.po`. Si cambió uno:

1. Compila ese dominio/locale a `.mo`.
2. Recarga el catálogo en `I18nService`.
3. Emite `LanguageChanged` para forzar el re-render.

Si el `.po` tiene un error de sintaxis, loguea y conserva el catálogo anterior;
no rompe la sesión. En release no hay watcher: los catálogos se cargan al
arrancar.

## Pseudo-locale y tests

`qps` se genera desde `en`: envuelve el texto en `[!! ... !!]` y acentúa las
vocales, preservando placeholders. Solo existe en dev/tests (`TOXINATOR_LANG=qps`)
y sirve para detectar strings hardcodeados y truncamiento.

Tests previstos:

- `tests/i18n/test_locale.py`: normalización, `LANGUAGE`/`LC_ALL`/`LANG`,
  precedencia del ajuste, `C`/`POSIX`, idioma no soportado.
- `tests/i18n/test_service.py`: `tr`, `trn`, placeholders, clave/parámetro
  faltante, aislamiento de dominios, cambio en runtime, formato de números/fechas.
- `tests/i18n/test_catalogs.py`: paridad, placeholders, fuzzy/vacíos/obsoletos,
  plurales, `.pot` fresco.
- `tests/i18n/test_controller_api.py`: endpoint, `lang`, solo `controller.*`.
- `tests/i18n/test_pseudo.py`: `qps` resuelve todas las claves y conserva
  placeholders.
- El test de frontera existente se extiende para prohibir `babel`/`gettext` en
  `games/`.

## Ejemplos

```python
# Launcher (dominio toxinator, proxy de la consola)
play = i18n.tr("launcher.featured.play")
players = i18n.trn(
    "launcher.players.one",
    "launcher.players.other",
    count,
    count=count,
)

# Juego (dominio maldito-pino, ctx.i18n ya viene bindeado)
ctx.i18n.tr("menu.start")
ctx.i18n.tr("hud.score", score=score)
```

```po
#: src/toxinator/launcher/home.py:42
#. Translators: botón principal de la ficha del juego.

msgstr "Jugar"
```
